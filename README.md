# dry_route — 濡れない経路・出発時刻ナビ

自転車/徒歩の移動で、気象庁の高解像度降水ナウキャスト（60分先まで）を使い、指定した経路上で
「いつ出発すれば雨に当たらないか」を判定するデモ。経路はOSRM（OpenStreetMap）で道路にスナップする。

> 元は [weather_hackathon_ideas](https://github.com/masauehr/weather_hackathon_ideas)（気象×生成AIハッカソン事前準備）のアイデア ID-15 として検証したもの。検証がGOだったため独立プロジェクトとして切り出した（2026-09-29）。

## 結論（先に）
| 問い | 結果 |
|---|---|
| 高解像度降水ナウキャスト（60分先まで）を無認証で取得できるか | **できた**。`jmatile/data/nowc/targetTimes_N2.json` で5分毎12コマの基準時刻・予測時刻一覧、タイルPNGも認証不要 |
| タイル画像から「その地点は雨か」を判定できるか | **できた**。タイルは256x256・4bitパレットPNGで、パレットindexごとに透明度(tRNS)が付いている。**実測で確認**: 「降水なし」の色（index0/1）はα=0、降水を示す色（index2以降=水色〜黄色等）はα=255。**αチャンネルだけで降雨の有無を機械的に判定できる**（正確なmm/h値は不要） |
| 出発時刻をずらす提案ができるか | **できた（実データで確認）**。奄美市名瀬（レーダーエコーの帯が接近中）の経路で検証: **0〜15分後・25〜30分後は0%（濡れない）だが、20分後だけ40%濡れる**とエコーの通過が正しく検出された |
| 実際の道路に沿った経路で評価できるか | **できた**。OSRM（`routing.openstreetmap.de`公開デモサーバー、認証不要）で徒歩/自転車の経路を取得（東京駅→皇居外苑で実測1823m、直線1366mより現実的）。3点以上の経由地にも対応。異常な迂回（山道の周回等）を検出したら直線にフォールバック |
| GO/NO-GO | **一部GO**。データ取得・道路スナップ・判定ロジックともに機械的に動く（下記「限界」） |

## Webアプリ
```bash
pip install -r requirements.txt
python server.py       # http://127.0.0.1:8793/
```
地図（Leaflet + OpenStreetMap）に気象庁の降雨タイルを重ねて表示。クリックで経由地を2点以上追加（出発地→...→到着地）し
「評価」を押すと、OSRMで道路に沿った経路にスナップした上で、出発時刻の候補（0〜60分後・5分刻み）ごとの推薦テーブルと、
選んだ候補の経路上の各点（🔴濡れる/🟢晴れ）が地図に表示される。テーブルの推薦行は比率に応じて緑(0%)/黄(50%未満)/赤(50%以上)に色分け。
スライダーで実況〜60分先までのナウキャストフレームを切り替え可能。

**GitHub Pagesのような静的常時公開はできない**（後述の「なぜサーバーが必要か」）。ローカルで動かすか、Render等のサーバーホスティングにデプロイする。

### 公開デプロイ（Render.com、無料枠・カード不要）
[render.yaml](render.yaml) を同梱（[jma_mcp_remote](https://github.com/masauehr/jma-mcp-remote) と同じ構成）。
1. https://render.com でGitHubアカウントでサインアップ
2. **New +** → **Blueprint** → このリポジトリを選択（`render.yaml` を自動検出）
3. 内容を確認して **Apply** するとデプロイが始まる（Instance Typeは無料枠）
4. デプロイ完了後、`https://dry-route.onrender.com`（または割り当てられた名前）が発行される

無料プランは15分間アクセスがないとスリープし、次回アクセス時に30〜60秒程度かかる。GitHubへのpush後の自動デプロイはRenderのサービス設定（Auto-Deploy）に従う。

## なぜサーバーが必要か（GitHub Pagesで公開できない理由）
- 降水ナウキャストは「今から60分先まで」しか意味を持たないデータで、静的サイトに事前計算した結果を置いても数分で無意味になる。
- 気圧配置の判定に使う `targetTimes_N2.json` 等のJSONにCORSヘッダーが無く、ブラウザから直接fetchできない（実測で確認。OSRMには`Access-Control-Allow-Origin: *`があり直接叩けるが、JMA側には無い）。
- 降雨タイルのピクセル（αチャンネル）読み取りも、CORS無しの画像をcanvasで読むとブラウザにブロックされる（tainted canvas）。
- この3点により、「JMAへの取得代行」をするサーバーが必須。`server.py`が気象庁・OSRMへの取得を代行し、結果だけをブラウザに返す。書き込みAPI・機密データは持たない読み取り専用の公開データ中継のため、DNSリバインディング対策のHostチェックは行っていない。

## 構成
| ファイル | 役割 |
|---|---|
| [fetch_nowcast.py](fetch_nowcast.py) | 高解像度降水ナウキャストの基準時刻・予測時刻一覧取得、タイルPNGの取得・αチャンネルでの降雨判定 |
| [route.py](route.py) | 経由地（2点以上）をOSRMで道路に沿った経路にスナップし、出発時刻を5分ずつ遅らせた候補ごとに「経路上の何点が濡れるか」を評価して最良の出発時刻を推す |
| [server.py](server.py) | ブラウザ向けAPI（`/api/frames`, `/api/route`）＋静的ファイル配信。ローカル・Render等のデプロイ両対応（`PORT`環境変数を読む） |
| [webapp/](webapp/) | Leaflet地図のデモUI（Vanilla JS） |

CLI実行: `python route.py walk`（徒歩4.8km/h） / `python route.py bike`（自転車15km/h）

## 仕組み
1. `targetTimes_N2.json` で直近の予測基準時刻と、60分先までの5分毎 validtime を取得
2. 経由地（2点以上）をOSRM（`routing.openstreetmap.de`）に渡し、道路に沿った経路のジオメトリと距離を取得（失敗時・異常な迂回時は経由地間の直線にフォールバック）
3. その経路を距離で等間隔の点に再サンプリングし、各点までの累積距離を計算
4. 出発時刻の候補（0, 5, 10, ... 60分後）ごとに、各点への到達予定時刻を歩行/自転車速度から算出
5. 到達予定時刻に最も近い validtime のタイル（緯度経度→Web Mercatorタイル座標→ピクセル）を読み、αチャンネルで「そのときその場所が雨か」を判定
6. 濡れる点が最も少ない出発時刻を推薦

## 取得元（入手性 / ライセンス / 粒度 / 遅延）
| データ | URL 系統 | 粒度・遅延 |
|---|---|---|
| 高解像度降水ナウキャスト | `https://www.jma.go.jp/bosai/jmatile/data/nowc/...`（気象庁 bosai） | 5分毎、実況＋60分先までの予測。250m格子相当 |
| 道路ルーティング | `https://routing.openstreetmap.de/routed-{foot,bike}/...`（OSRM、OpenStreetMapデータ） | OpenStreetMapの道路網に基づく徒歩/自転車ルート |
入手性はいずれも認証不要。気象庁データは気象庁HP利用規約（出典明記）に従う。OSRMの公開デモサーバーは**デモ用途のみ**（商用・大量アクセス不可、[利用規約](https://routing.openstreetmap.de/)）。地図タイルの出典はOpenStreetMapコントリビューター。

## 発見・注意（実装上のハマりどころ）
- **タイルはパレット形式（最大16色）で、各パレットindexにtRNSで透明度が入っている**。実測（東京駅付近）では index0,1（白・透明）がα=0、index2〜6（薄い水色→水色→青→濃い青→黄色、降水強度が強いほど濃い色）がα=255。厳密なmm/h値を知らなくても「降水の有無」は確実に判定できる。
- **JMAのhrpnsタイルは奇数ズーム（5,7,9）で空タイル（334byte）を返す**（実測で確認、気象庁側の仕様）。`_getZoomForUrl`をオーバーライドしてURLのzだけ書き換える対処は、タイル座標(x,y)が元のズーム用のまま残るため地理的に不整合なタイルを要求してしまい失敗する（実際に表示は空白のままだった）。正しい方法は、ズーム変更時に`minNativeZoom=maxNativeZoom=有効な偶数ズーム`に固定したレイヤーを作り直すこと。
- **OSRMは稀に極端に迂回した経路を返す**（山道の周回等）。直線距離の3倍を超えたら信頼せず直線にフォールバックする安全策を入れている。
- 「経路全体の濡れる比率」が最良（最小）でも、それが50%を超えるなら緑ではなく赤で警告表示にする（相対的な最良を絶対的な安全と誤解させないため）。

## 限界（過大評価しないために）
1. **降雨の強度（弱い/激しい）を区別していない**。二値判定（濡れるか否か）のみ。強度別の重み付けは未実装（パレット色の相対順位を使えば拡張可能）。
2. **60分先までしか予測がない**（`hrpns`の高解像度ナウキャストの範囲）。長距離・長時間の経路には対応しない。
3. `routing.openstreetmap.de`は**デモ用途の公開サーバー**（利用規約上、商用・大量アクセス不可）。本番運用には自前ホストか有料APIが必要。
4. タイル座標のピクセルサンプリングは1点のみ（周辺ピクセルの平均化などはしていない）。
5. 経由地の指定は地図クリックのみ（住所検索・現在地取得は未実装）。
